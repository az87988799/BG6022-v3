# M1 milestone handoff

M1 adds the first natural-language Agent on top of the accepted M0 execution
boundary. The production Tool directory is:

```text
resolve_molecule -> generate_geometry -> optimize_geometry
                                  \-> single_point (when explicitly requested)
```

`resolve_molecule` uses PubChem for names/CAS/CID and RDKit for explicit SMILES.
`generate_geometry` uses bounded ETKDGv3 seeds and records an initial-guess
artifact. ORCA remains the only real compute boundary and the original geometry
is never overwritten.

Implemented in this stage:

- strict chat/intake/plan/repair schemas and a single bounded DeepSeek client;
- generic Tool registry validation, structured result targets, and current
  successful-result bindings;
- bounded PubChem lookup and RDKit geometry generation;
- one confirmation point, accepted execution snapshot, same-Run continuation,
  Opt restart repair rules, and conservative SCF repair admission;
- bounded session JSON, chat commands, packaged prompts, and the `chat` command.

Offline implementation status: complete for the checked-in code path. The
following live acceptance remains pending user execution/review: a real
DeepSeek plan, real PubChem water/ethanol preparation, a normal real Opt from
chat, and a real `geom_maxiter=1` Opt failure followed by a real LLM-selected
restart and successful second attempt. This file must not be changed to
“accepted” until the user explicitly accepts M1.

Validation commands:

```powershell
.venv\Scripts\python.exe -m pytest -m "not live_orca and not live_llm and not live_pubchem"
.venv\Scripts\ruff.exe check src tests
.venv\Scripts\ruff.exe format --check src tests
.venv\Scripts\python.exe -m compileall -q src start_chat.py
.venv\Scripts\uv.exe build
```

Live tests are opt-in and require the corresponding configuration, credentials,
network permission, and ORCA executable. Fakes and mock transports are labeled
as offline evidence and do not count as live acceptance.
