# M1 milestone handoff

M1 adds the first natural-language Agent on top of the accepted M0 execution
boundary. The production Tool directory is:

```text
resolve_molecule -> generate_geometry -> optimize_geometry
                                  \-> single_point (when explicitly requested)
```

`resolve_molecule` uses PubChem for names/CAS/CID and RDKit for explicit SMILES.
`generate_geometry` uses bounded ETKDGv3 seeds and records an initial-guess
artifact. ORCA remains the only real compute boundary and the original geometry
is never overwritten.

Implemented in this stage:

- strict chat/intake/plan/repair schemas and a single bounded DeepSeek client;
- generic Tool registry validation, structured result targets, and current
  successful-result bindings;
- bounded PubChem lookup and RDKit geometry generation;
- one confirmation point, accepted execution snapshot, same-Run continuation,
  Opt restart repair rules, and conservative SCF repair admission;
- bounded session JSON, chat commands, packaged prompts, and the `chat` command.

The 2026-09-11 minimal-repair pass additionally preserves the original Request
operation and result targets, scopes q/M to explicit user input or the current
geometry's validated molecule facts, returns the resolved ORCA Step used for
preview/fingerprint/execution, and keeps waiting states ahead of intermediate
preparation results. It records the effective geometry MaxIter from ORCA's
geometry-settings block, admits only bounded same-Run Opt restarts backed by
the failed Result and restart candidate, and rejects tampered resources,
Requests, Plans, or repair records at the execution boundary. Request-level
cancellation now covers intake, planning, network calls, and the CLI worker.

The current new-Run resource baseline is 4 cores, 1024 MB total, `%maxcore
192`, and one concurrent ORCA job. Historical 2048 MB evidence in M0 records
is unchanged; existing Runs retain their own resource snapshots.

Implementation and real Agent-path L1/L2 execution are complete for the
checked-in code path. M1 remains pending the user's review and explicit
acceptance; this file must not be changed to “accepted” until the user accepts
it.
